## Contraction timer

- **`contraction-tracker/index.html`** — the whole app (vanilla JS, no build). Key symbols:
  - `pull` / `pushState` / `applyRemote` / `touch` — sync protocol: full-state last-write-wins, `revision` = `Date.now()` of last local mutation; poll every `POLL_MS` (4s) + on visibility/online.
  - `updateMainUI` — single place button/timer reflect `active`; called for both local taps and remote adoption. `tick` interval guard lives here.
  - Sync room comes from `#r=<id>` URL fragment (kept out of this public repo on purpose), then persisted in `localStorage[ROOM_KEY]`. No fragment ever seen → local-only mode.
  - `localStorage` v2 schema `{revision, contractions, active}`; one-shot migration from v1 in `load()`.
  - Theme: `data-theme` on `<html>`, CSS vars per theme, per-device pref in `localStorage['ctTheme']` (NOT synced). Inline head script applies it pre-paint.
  - Avg window: `#avgWindowSel` picks the span for the two avg stats — a contraction count (`5`/`8`/`10`) or a time span (`15m`/`30m`/`60m`/`120m`); per-device pref in `localStorage['ctAvgWindow']` (NOT synced). `windowSetForGaps`/`windowSetForDuration` resolve it against `contractions`; a 15s interval re-renders while a time-based window is active so contractions age out without a new tap.
  - `editRow`/`deleteRow` — per-row ✎/✕ via event delegation on `#logList` (`data-edit`/`data-del`); edit re-sorts by `start`, both call `touch()` to sync.
  - Deploy habit: snapshot live KV state to `backups/` (gitignored — room id is the credential) BEFORE pushing app changes.
- **`contraction-tracker/worker/index.js`** — Cloudflare Worker `contraction-sync` (KV binding `STATE`). GET/PUT `/state/:room`, CORS `*`, validates JSON + numeric `revision`.

Local gotchas:
- Conflict model is wholesale LWW — two devices mutating in the same poll window can clobber one tap. Accepted: one person logs in practice.

## Baby activity tracker

Local-first multi-device tracker. UNLIKE the contraction timer's wholesale LWW, sync is **entry-level merge** (see `sync.js`) so several caregivers logging concurrently never lose taps.

Installable PWA (`manifest.webmanifest` — has `id` + the page has `application-name` metas so Android recents shows "Baby Tracker" instead of "Web app"; a stale WebAPK may need uninstall/re-add to pick the name up — `sw.js`, generated icon PNGs) with web push alerts: shared alert rules live in the synced state (`alerts` key) and are evaluated **server-side** by the worker's cron so notifications arrive with the app closed; the push subscription itself is per-device.

- **`baby-tracker/sync.js`** — pure merge logic, no DOM (loaded by the page, eval'd by node tests). `normalizeState`/`mergeState`/`stateSig`. State: `{revision, entries, active, alerts, alertsRev, baby:{name,born,sex}, babyRev, deleted, archivedBefore}`. Merge rules: entries union by `id` with higher `mt` (modified-ts) winning; deletes are tombstones in `deleted{id:ts}` (60-day TTL) that beat presence; `active` slots resolve by `mt` and are cleared when their stop-entry (`'s'/'n'+start`) exists; `alerts` is wholesale LWW by `alertsRev`; `baby` (name/born/sex) is wholesale LWW by `babyRev`; entries older than the server watermark `archivedBefore` are dropped (they live in archives). `stateSig` is a key-order-independent content signature used after each pull to decide adopt vs push — prevents push churn loops.
- **`baby-tracker/index.html`** — vanilla JS, no build. Key symbols:
  - Diaper and pump type icons are inline SVG `<symbol>`s (`#icoDiaper`/`#icoPump`, top of `<body>`; no emoji exists for either) referenced via `<use>`; `.svgico` is 1em so they scale with the surrounding font-size, and the JS-side strings live in `ICO_DIAPER`/`ICO_PUMP` (action buttons, timeline lane, filter chips, alerts row, log rows). Diaper *kind* markers stay 💧/💩 emojis.
  - Entry shape: `{id, type, start, end?, duration?, mt, by?, note?, ...type-specific fields}`; `type` is one of `sleep`/`nurse`/`bottle`/`diaper`/`solid`/`med`/`pump`/`health`/`bath` (bath: note only, id prefix `w`, auto-wakes a running sleep). `nurse` has `side` (`L`/`R`/`both`); `bottle` has `amount`/`unit`/`milk`; `diaper` has `kind` (`wet`/`dirty`/`both`); `solid` has `food`; `med` has `name` (last name remembered per device in `btLastMed_v1`); `pump` has `amount`/`unit`/`side`; `health` has any of `temp`/`weight`/`length` — weight is entered/shown in GRAMS; legacy entries stored kg, normalized display-side by `toGrams` (values <100 = kg), CSV column `weight_g`. `stamp()` sets `mt` + `by` (per-device name, `btDeviceName_v1`, set in the 🔔 modal) on creation; every edit bumps `mt`.
  - Quick-log modals assume "today" for their time field; `applyTimeBack` treats a future-looking time as yesterday (night logging around midnight).
  - `editRow`/`deleteRow` address entries **by id**, not index — a 10s poll can reorder the array while a dialog is open. Deletes write a tombstone.
  - Log list renders newest-first: today's entries capped at `todayLimit` (5, "Load more… (N earlier today)" reveals the rest), then past days as collapsible one-line `▸` summary headers (feeds/diapers/sleep, or `n × icon` when filtered) limited to `pastWeeks × 7` sections ("Load more… (N earlier days)" adds a week), plus a type filter chip row and an Expand all / Collapse all button in the Log heading; the day-collapse state is an in-memory Set (`expandedDays`) so sync re-renders don't reset it, while the filter persists per device (`localStorage['btLogFilter']`); changing the filter resets both paging counters; `renderHistory` shows the last 7 days (`histDays`, "Show earlier days" +7 while older hot-window data exists) topped by an accent-colored average row over a selectable window — 7d/14d/1m toggle on the heading, per-device pref `localStorage['btAvgSpan']` — of FULL days (today excluded as partial; fewer if the log is younger, label shows the real count) — columns: feeds with total nursed minutes in parens / bottle ml / sleep / diapers; the Today stat card shows the same nursed-minutes suffix; `csvBtn` exports full history to CSV, fetching server archives on demand.
  - Weight chart (`renderGrowth`/`growthPoints`/`lmsWeight` + `WHO_WFA` girls/boys LMS table, `#growth`): a WHO Child Growth Standards weight-for-age chart (0–6 months in this first version) drawn as inline SVG — shaded 3rd–97th / 15th–85th percentile bands + median line for the configured `baby.sex`, with the baby's own `health` weights (grams→kg) overlaid by age as a pink line + dots. Curves are computed from the embedded WHO LMS parameters via `M·(1+L·S·z)^(1/L)` (matches the published WHO percentile tables). Needs both `baby.born` and `baby.sex` (synced, set in the 🔔 modal — a `<select>` next to the birth date; unset → a hint that deep-links into settings, so nothing sex-specific is defaulted in this public repo). Weights older than the 35-day hot window are archived, so a one-tap "Show earlier weights" (`loadGrowthArchive`) pulls the archive months overlapping 0–6 mo on demand — the same fetch CSV export uses, user-initiated, so **no recurring KV cost** (budget unchanged). Theme-aware via CSS vars; re-rendered by `render()` and on baby-config change.
  - `active = { sleep, nurse }` — two independent in-progress timers (mirrors the contraction timer's single `active`, just two of them since sleep and nursing can each be running/tracked concurrently). Tapping Sleep/Nurse while *idle* opens that type's modal (`openSleepModal`/`openNurseModal`): "Start timer" OR log an already-finished session via `makeWheel` scroll-snap wheel pickers (nurse: minutes 1–90; sleep: hours 0–16 + minutes step 5) — entry is backdated `end = now, start = end − duration`. Tapping while *running* stops directly, no modal. Bottle/Diaper/Solids are instantaneous events logged via a small modal (time defaults to now, editable). Logging nurse/bottle/diaper/solid/med while the sleep timer runs auto-stops the sleep at that event's time (`autoWake`) — events dated before the sleep began leave it running, and pump (mother's activity) / health (temp checks on a sleeping baby) never end it.
  - Login gate (`doLogin`/`sha256Hex`): full-screen `#loginOverlay` blocks the app until the shared password is entered; page embeds only `PASS_SHA256` (sha256 of the password — brute-forceable for a short password, accepted: it's bot deterrence, not security). The sync room id is *derived* from the password (`sha256('baby-room-v1:'+pw)` first 32 hex chars; an optional per-baby slug from the login form makes it `'baby-room-v1:'+pw+':'+slug` — one room per baby) so it never appears in the repo and every signed-in device lands in the same room automatically — no `#r=` link (that mechanism was removed from this app; the contraction timer still uses it). Persisted in `localStorage['babyAuthRoom_v1']`; presence of that key == signed in (no logout UI). `crypto.subtle` needs a secure context — https or localhost.
  - `pull`/`pushState`/`touch` — poll every `POLL_MS` (github.io 10s / self-hosted 3s via `SELF_HOSTED`; on Pages one always-open tab ≈ 8.6k reads/day against the 100k/day free KV/Workers quotas; the interval skips polling while the tab is hidden, and visibilitychange pulls on return) + online pulls; `pull` merges via `mergeState` and pushes only when `stateSig` says the remote actually lacks something. Own localStorage key (`babyLog_v1`), own Worker (`SYNC_URL`).
  - Alerts UI (`RULES`/`paintAlertRules` + 🔔 modal): four rules — feed/diaper gap, awake-too-long, asleep-too-long — each `{on, min, crit}` (`crit`: `low`=silent/once, `normal`=sound/repeat 30 min, `high`="Nag" sound/repeat 10 min + sticky/renotify, `alarm`=strongest push every 5 min + rings locally), plus `quiet` hours `{on, from, to, tz}`. Rules are PER DEVICE: stored in `localStorage['btAlertPrefs_v1']` (`alertPrefs`, seeded from the old shared config on first run) and uploaded with the push subscription (`subscribePush` sends `{...sub, alerts}`); `savePrefs` also dual-writes into the legacy synced `alerts`/`bumpAlerts` field so an un-redeployed worker keeps working. Push side: `subscribePush`/`ensurePush`/`updatePushUI`, `VAPID_PUBLIC` embedded for github.io / `vapidKey()` fetches `/vapid` when self-hosted, per-device enabled flag `localStorage['btPushOn_v1']`; `ensurePush` re-POSTs the subscription on every load to survive push-service rotation. `updateSrvStatus` (modal open) POSTs `/status/:room` and shows last-cron-run + device-registered diagnostics. iOS: push only works installed to Home Screen (`isStandalone` check shows the hint).
  - Ringing alarm (`evalLocalAlarms`/`dueAlarmRules`/`stopAlarm` + `#alarmOverlay`): rules with crit `alarm` ring like a timer on any device where the app is open — WebAudio beep loop (unlocked on first pointerdown; silent until first user gesture) + vibration + full-screen stop overlay; evaluated every 15s and in `render()` so logging the activity (any device, via sync) silences it instantly; Stop snoozes 15 min (`ALARM_SNOOZE_MS`), condition clearing resets the snooze; respects per-device quiet hours (`localQuiet`).
  - `sw.js` — push + notificationclick handlers; same-origin GETs are network-first with cache fallback (offline works, deploys are never stale).
  - `renderTimeline` — activity strip with a 6h/12h/24h/3d/7d span toggle (per-device pref `localStorage['btTlSpan']`), one lane per type (`TL_TYPES`, 9 lanes, diaper third after sleep/nurse): bars for sleep/nurse (incl. live `active` timers; nurse bars carry an L/R/B side letter), kind icons 💧/💩 on the diaper lane, dots for the rest. X-axis shows hour-aligned clock times (`tlTicks`; 6h/3h/2h label steps by span) with matching gridlines in the lanes, and dragging on the lanes places a scrubber line (`tlCursor` fraction + `paintTlCursor`) whose bubble shows the exact time / "ago" at that point — tap the bubble to dismiss; position survives re-renders. Re-rendered by `render()` + a 15s interval. Spans >24h switch to `renderTimelineDays`: one clock-aligned row per day (newest top; `today`/`yday`/weekday labels), TWO BANDS per row — sleep bars on top, nurse bars below, every other type as dots — filtered by a multi-select type-chip row (`tlDayTypes`, per-device `btTlDayTypes_v1`, defaults sleep+nurse+bottle); live timers included, `.tlnowline` marks now on today; built for comparing same-time-of-day patterns (evening cluster feeds); the drag scrubber is ≤24h-only (guarded in `pointerdown`).
  - Layout: ≥760px (tablet / phone landscape) switches to a two-column grid (`.cols` — left: stats, action buttons, Weight growth chart; right: timeline, log, daily history). The Weight block lives in the left column in the DOM (so on phone it stacks under the buttons too). The ⚡ top-bar button toggles a per-device "quick" mode (`localStorage['btUiMode']`): `body.quick` hides everything marked `.fullonly`, leaving only enlarged action buttons (4-across when wide) — works in both orientations.
  - `agoOr`/`lastOfType` — "X ago" sub-labels on all action buttons (refreshed in `updateStats`; running timers own their sub text via `updateActionUI`/`startTick`).
  - Age-aware urgency colors (`AGE_BANDS`, `ageThresholds`; birth date comes from the synced baby config — unset = no coloring, and it is deliberately NOT defaulted in this public repo; the header shows an age chip next to the name — `babyAgeLabel`: days under a month, then months+days, refreshed by the 15s interval): the feed/diaper/awake gaps turn orange (`.warn`) then red (`.late`) on the stat cards and the Nurse/Diaper/Sleep button subs at limits that loosen with age (newborn: feed 2.5/3.5h, diaper 3/4h, awake 1/1.5h → 12m+: feed 5/6h, diaper 5/6h, awake 4/5.5h). Nurse's color uses the overall feed gap (a bottle resets it) and pauses while nursing; awake color pauses while the sleep timer runs.
  - Edit modal has a date field (`combineDateTime`) so an entry can be moved to another day (e.g. mis-logged across midnight); sleep/nurse end times resolve on the start's day, an earlier clock time meaning midnight was crossed. It also shows/hides field groups per type (`editEndWrap`, `editSideWrap`, `editAmountWrap`, `editMilkWrap`, `editKindWrap`, `editFoodWrap`, `editMedWrap`, `editHealthWrap`); pump reuses amount+side wraps.
  - Theme: `localStorage['btTheme']` (separate from the contraction timer's `ctTheme`, per-device, NOT synced).
- **`baby-tracker/worker/`** — separate Cloudflare Worker `baby-tracker-sync`, its own KV namespace `BABY_STATE` (bound as `STATE` — binding name must stay `STATE` to match `env.STATE` in the worker code). Same GET/PUT `/state/:room` contract as the contraction timer's worker, plus push:
  - `webpush.js` — dependency-free Web Push sender (`sendPush`/`encryptPayload`/`vapidHeaders`): RFC 8291 aes128gcm + RFC 8292 VAPID via WebCrypto. Verified by an offline encrypt→decrypt round-trip test. VAPID private key = worker secret `VAPID_JWK` (JWK JSON, set via `wrangler secret put`, NEVER in the repo); the public key is embedded in `index.html` (github.io path) and served by `GET /vapid` (self-hosted path; route added 2026-08-08 mirroring pelvic). Apple rejects JWTs with exp >24h — we use 12h.
  - `index.js` — `POST /subscribe|unsubscribe|test|status|log/:room`, `GET /summary/:room`, `GET /archive/:room[/:month]`; `POST /log` appends one validated entry server-side (types diaper/bottle/nurse/sleep/solid/med/bath + `ago_min`/`note`/`by`, default by "Home Assistant", ids/mt match client conventions, bumps `revision` so clients pull it within a poll; sleep/nurse also take `{action:'start'|'stop'}`) — the Home Assistant path, room id = credential (copyable from the 🔔 modal); `GET /summary` returns gaps/today-counts JSON (Europe/Oslo "today") for external sensors — poll it at ≥120s (budgeted ≈720 reads/day); `scheduled` (cron `*/5 * * * *` in wrangler.toml) runs `checkAlerts` + `dailyMaintenance`. `/subscribe` stores the device's alert prefs alongside the subscription (`{endpoint, keys, alerts?}`); `/status` returns `{lastCron, devices, subscribed}` for the in-app diagnostics line (`cron:last` heartbeat key, written at most every 30 min to spare the 1k/day KV write quota).
    - Subscriptions are stored as ONE blob per room (`subs:<room>` map keyed by endpoint hash) plus a `subsrooms` index, so the every-5-min cron does zero KV LIST operations — the free tier allows only 1k lists/day and the old per-key scheme burned ~600/day here (the cause of the July 2026 quota-warning emails). Legacy `sub:<room>:<hash>` keys migrate in lazily on first access and are deleted; identical re-subscribes skip the write.
    - `checkAlerts` (exported for tests): iterates `subsrooms`, evaluates `dueAlerts` PER DEVICE against that sub's own `alerts` config (fallback: the room state's legacy shared config for not-yet-updated clients; `dueAlerts` exported for tests; mirrors client stats logic, silent on empty logs, nursing/sleeping suppress feed/awake alerts; also always-on forgotten-timer guardrails `NURSE_TIMER_MS` 2h / `SLEEP_TIMER_MS` 14h), dedups via `alerted:<room>` map keyed `<deviceId>:<rule>` — fires on crossing, repeats per criticality (`REPEAT_MS`: low never / normal 30 min / high 10 min / alarm every cron run) while the condition holds, resets when it clears; low-crit pushes go out with `Urgency: normal`. `inQuietHours` (exported) is evaluated per device with that device's quiet config (tz via `Intl`; invalid tz fails open); suppressed alerts fire when the window ends.
    - `dailyMaintenance` (gated by `maint:last` date key, discovers rooms by listing `room:` keys): snapshots each room to `backup:<room>:<date>` (14 kept), then moves entries older than `HOT_DAYS` (35) into `archive:<room>:<YYYY-MM>` keys (union by id) and sets the `archivedBefore` watermark + a new revision on the trimmed hot state — this is what keeps the hot blob under the worker's 500KB PUT limit forever. Archived entries are read-only (history/CSV); clients drop them from hot copies via the watermark. 404/410 push responses prune the subscription.
- To share the baby tracker across devices, just sign in with the shared password on each device (room is derived from it — see login gate above).

## Pelvic trainer

Guided pelvic floor (Kegel) trainer with synced session log + push reminders. Protocol follows NHS/NICE-style PFMT guidance (slow holds building to 10s ×10 + quick squeezes, 3 sessions/day). Installable PWA (manifest `id`, generated flower icon PNGs, `sw.js` network-first + push). Login gate uses the SAME family password as the baby tracker but a different room salt (`sha256('pelvic-room-v1:'+pw)` → `localStorage['pfAuthRoom_v1']`), so its data is a separate KV entry — and changing the shared password moves this app's room too. Main screen is compact (today card / start / plan / calendar); reminders and the technique guide live behind 🔔 and 📖 top-bar modals.

- **`pelvic-trainer/index.html`** — vanilla JS, no build. Key symbols:
  - Sync (`pull`/`pushState`/`mergeSessions`/`logSig`): sessions-only state `{revision, sessions:[{id,...}]}`, union-by-id merge (sessions are never deleted → no tombstones), poll every 60s (skipped while hidden) + visibility/online; `finishSession` pushes immediately. Pre-sync local entries get `id = 's'+ts` on load.
  - Session player (`buildSchedule`/`sessTick`/`startSession`): phase schedule = 3s prep → reps×(hold+rest) → 4s transition → quicks×(1s on/1s off); 100ms tick computes phase from elapsed wall time (drift-free, pausable via `pausedTotal`); animated circle scales per phase (transition duration matched to phase), WebAudio tones (unlocked on first pointerdown) + vibration cues per phase change, screen wake-lock held during a session (re-grabbed on visibilitychange).
  - Presets `PRESETS` (gentle 3s×8 / building 6s×10+5 / full 10s×10+10) + custom hold/rest/reps/quicks editor; config in `localStorage['pfCfg_v1']`.
  - Progress: sessions log `pfLog_v1` (`{ts, hold, rest, reps, quicks, preset}`); 3-dot today row, streak (consecutive days ≥1 session, today-not-yet-done doesn't break it), 5-week calendar heatmap (`paintProgress`), level-up hint after 5 days of ≥2 sessions on a non-full preset.
  - Reminders (🔔 modal): up to 3 per-device times (`pfRem_v1`) + enable toggle (`pfPushOn_v1`); the VAPID public key is FETCHED from the worker (`GET /vapid`, cached `pfVapid_v1`) so no key is hardcoded; `subscribePush` POSTs `{sub, times, tz, room}` (room lets the cron skip nudges once 3 sessions are logged that day); `ensurePush` re-POSTs on every load. Theme `pfTheme` (per-device).
  - Technique section: muscle identification, breathing/no-glutes rules, vaginal vs c-section start timing, the Knack, physio red flags + not-medical-advice note.
- **`pelvic-trainer/worker/`** — Cloudflare Worker `pelvic-reminders`, own KV namespace (binding `STATE`), own VAPID keypair (`genvapid.mjs` generates the JWK locally → `wrangler secret put VAPID_JWK`; public key served by `GET /vapid`). Routes: `GET/PUT /state/:room` (session-log sync, 200KB cap), `POST /subscribe|unsubscribe|test`, `GET /vapid`. All subscriptions live in ONE `subs` blob (keyed by endpoint hash; legacy `sub:<hash>` keys migrate in lazily) so the cron reads a single key instead of LIST-scanning; re-subscribes preserve the `sent` markers and skip the write when unchanged. Cron `*/5` runs `sendReminders` (exported for tests): per sub, compares the sub's local time (its stored `tz` via `Intl`) against its `times`, fires once per slot per local day (`sent` map, all updates aggregated into one blob write per run), skips the nudge when the sub's `room` already has 3 sessions that local day, prunes 404/410 endpoints. `webpush.js` is a copy of the baby tracker's sender. First-deploy setup: create KV namespace (`npx wrangler kv namespace create STATE`, paste id into wrangler.toml), set `VAPID_JWK` secret, deploy.

## Self-host server (`server/` — in flight, see RJ 2026-08-08)

The home-server replacement for GitHub Pages + the three CF Workers. The worker files stay the single source of behaviour — the harness bridges them **unchanged**. Deployment topology and the run-book live in the PRIVATE homelab config (per the CLAUDE.md privacy rule, infra details stay out of this public repo); `server/DEPLOY.md` here is only a pointer stub.

- **`server/kv.js`** — `makeKV(dir)`: file-per-key drop-in for the KV subset the workers use (get/put/delete/list-prefix, strings); `:`→`~` filename mapping (no worker key contains `~` — guarded in `put`); atomic tmp+rename writes.
- **`server/server.js`** — static serving (MIME allowlist; `DENY` set blocks `server/`, `*/worker/`, `homeassistant/`, bible docs, `package.json`; html/js sent `no-cache` — kills the Pages max-age=600 staleness class; icons 1 day) + `/api/{baby,pelvic,contraction}/*` bridge (`bridge()`: body buffered ≤1.5MB, only content-type forwarded) + `cronTick` every `CRON_MS` (5 min, overlap-guarded, `waitUntil` shim) + `GET /healthz` + `POST /admin/cron` (idempotent manual pass — maint is date-gated, alerts dedup'd). Env: `PORT` 8080 / `DATA_DIR` /data / `BABY_VAPID_JWK` / `PELVIC_VAPID_JWK` (a missing JWK disables that app's push/cron, sync still works).
- **`server/tools/migrate.mjs`** — cutover copier: derives rooms from the family password (+optional slug), writes snapshots into `backups/migrate-<ts>/` FIRST, PUTs to the target, GET-back **byte-identical** verify; `--dry-run`; downloads + warns on any existing archive months (manual placement).
- **`Dockerfile` / `docker-compose.yml`** — node:22-alpine, `USER node` (uid 1000 — the data volume must be owned accordingly), host port 10700, `env_file: .env` (untracked → survives `git reset --hard` deploys).
- **`.github/workflows/deploy.yml`** — CI joins the tailnet and deploys over SSH; the server-side key is command-restricted, so the inline script is effectively documentation. This repo's branch is **main**.
- Cross-app contract: every app defines `SELF_HOSTED` (`!/\.github\.io$/i` on hostname) + a gated `MOVED_BANNER` (cutover switch) next to its config consts; both sw.js skip `/api/*` and bumped caches (`bt-v3`/`pf-v2`); the baby worker now serves `GET /vapid` like pelvic.

Local gotchas:
- The boot-time first cron tick claims `maint:last` for the UTC day — data imported after boot gets its first daily backup the NEXT day (`migrate.mjs` snapshots cover day 0); `/admin/cron` deliberately doesn't override the gate.
- WHATWG URL normalizes `../` before handlers ever see it, so the traversal guard is a backstop, not the first line; root files with servable extensions must be DENY-listed explicitly (`package.json` is).
